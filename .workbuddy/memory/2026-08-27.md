## 沉淀"claim-lifecycle"技能（通用方法论版）

DY 认为"猜想-核实-迭代"自生命周期知识库很好，要求形成一个技能/专家、面向更广应用、产出不只代码上下文注入。经 AskUserQuestion 确认三项决策：**技能形态 · 通用方法论 · 全覆盖产出**。已在用户级创建技能 `~/.workbuddy/skills/claim-lifecycle`。

### 技能结构
- **SKILL.md**：五阶段生命周期旅程（采集 Capture → 打标 Label → 锚定 Anchor → 核实 Verify(人工周报) → 产出 Deliver），含核心概念速查、快速开始、触发指引、资源索引。
- **scripts/**（纯 Python stdlib，可移植）：
  - `extract_claims.py`：对话/笔记 → 主张卡（JSON + 可选 YAML 导出），启发式分 kind。
  - `anchor_claims.py`:保守三级锚定（T0/T0* 字面 score≥100 → literature_supported；弱锚 → consistent；无锚 → unverified），双后端：`--index`(MCP sqlite，course_material_mcp) / `--corpus`(免依赖 token-overlap)。
  - `report_generator.py`：**多形态产出**（inspect/weekly/tickets/audit/inject[code_context|teaching_material|design_constraint]）。
  - `validate_registry.py`：受控值 + 分轨一致性校验（可作 CI）。
- **references/**：metadata_schema.md（字段/双轴/rank 表/分轨）、lifecycle.md（状态机/机器职责边界/门控）、delivery_modes.md（7 种产出形态矩阵）、pitfalls.md（工程陷阱：自锚定失真、机器不升级、弱锚漂移、门控在检索层、双轴不合并、状态机粒度、拉活节点、测试维护）。
- **assets/claims_registry_template.json**：开箱模板。

### 关键设计考量
- 面向通用：脚本零 MCP 强依赖（默认 --corpus 引擎），`--index` 仅在可导入 course_material_mcp 时增强。
- 产出多元化是核心诉求：同一 registry 驱动 inspect(库检定期报告)/weekly(核实周报)/tickets(验证工单)/audit(追溯审计)/inject(三类注入包)，所有形态**先过门（rank≥2 且 provenance∈{literature,own_publication}）再格式化**。
- 守住黄金法则：机器只锚定不升级、hypothesis 永不注入、门控在产出/检索层。

### 验证
- 端到端冒烟通过：4 条对话主张 → 抽取 → 校验(0 error) → corpus 锚定（1 literature_supported / 1 consistent / 2 unverified，与预期一致）→ inspect/weekly 产出正常。
- 修复 1 个 bug：extract_claims.py 的正则 `?=.*正确` 无效 lookahead → 改为 `是否.*正确`。
- 打包校验通过：skill-creator package_skill.py 生成 `claim-lifecycle.zip`（26KB）。
- 安装位置：用户级 `~/.workbuddy/skills/claim-lifecycle/`，任意工作区可用。
