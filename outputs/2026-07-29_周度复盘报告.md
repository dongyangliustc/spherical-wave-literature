#### 突出的 Bug 与修复

1. **G.3 Critical Bug（7/23）**：`_spherical_harmonic_cartesian_terms` 返回扁平列表，Y_lm 的多项 Cartesian 表示（如 Y_2,0 = 3z²−1）被误作独立 m 处理。导致 l>0 时产生 3-47% 伪贡献（大 κ 时 >3000%）。修复方案：将 Y_lm 转化为齐次 degree-l 多项式表示，按 m 分组合并后单次积分。**这属于 AI 生成代码中的深层数学 Bug，人工审查可能难以发现**——暴露了自治代码开发中数学验证的天然盲区。

2. **G.4 归一化因子缺失（7/24）**：Born 修正缺失 (2π)^(-3/2) FT 归一化因子，导致 Born correction 偏大 15-250 倍。R_p 符号错误（多中心场景）。两项修复均经 Code Reviewer 发现。

3. **G.7 K-sum 公式错误（7/28）**：K 矩阵 mu<nu 仅计算 (αμ|βν)，缺失交叉项 (αν|βμ)，导致 He K 20% 误差。双电子积分 8 重对称性不允交换 bra-ket。

4. **G.6 Bessel overflow（7/26-28 间）**：Born 核中的 modified spherical Bessel i_l(κ) 在大 κ 时数值溢出，创建了专门的 `_scaled_il_gauss` 修复。

## 三、我的 Agent 使用优化建议

### 3.1 提问方式

**问题**：存在"先动手、后排查"的倾向。例如 scansci-pdf 配置中，SSL 兼容性问题在第 3 轮排查才确认根因。

**建议**：
- 涉及环境配置、网络依赖的任务，在提问时附带关键环境约束（如："当前网络有企业防火墙，优先使用 CLI 直接下载而非浏览器自动化"）
- 使用**约束前置**模式：先声明已知限制，再给任务目标。例如：
  > ❌ "帮我配置 scansci-pdf"  
  > ✅ "帮我配置 scansci-pdf。当前环境：Windows，Python 3.13 有 SSL 兼容问题，请优先使用 miniconda 3.13.9 venv，跳过 browser automation 方案。"

### 3.2 任务拆解习惯

**问题**：任务拆解缺少明确的"结束条件"和"交付物定义"。例如 SW Master Agent 的 G.6 Gate 执行经历了多次中断重试，因为 Gate 的条件（6 项标准的通过阈值）不够精确。

**建议**：
- 对于每个子任务，明确 3 个要素：
  1. **最小可验收产出**：哪怕不完全，什么产出可以"先交作业"？
  2. **通过/失败标准**：可量化的数值目标（如"Born correction 使 L/V ratio < 10"）
  3. **最大迭代次数**：避免无限重试循环
- SW Master Agent 的 Gate Check 条件应从"PROMOTE_WITH_CAVEATS"这类模糊判定，改为具体量化指标。

### 3.3 目标定义方式

**问题 1：知识产出与代码实施脱节**

文献调研项目产出了约 376 KB 的高质量笔记，SW Master Agent 产出了 430K+ 字符的代码，但两者之间只有单向的 MCP 关键词检索——笔记中的分析结论（如"四种方法的根本局限对比"、"融合趋势判断"）从未影响 SW 项目的技术决策。

**建议**：
- 在 Phase G（或下一大阶段）开始前，明确要求：**先花 30 分钟阅读文献项目中的特定笔记**（如《分子连续态量子化学方法对比报告》第 9 节"对本项目的启示"），再根据阅读结论调整 Spec 中的技术参数。
- 将 MCP 连通器从"每次运行关键词检索"升级为"每 Phase 开始时读取一篇完整笔记摘要作为上下文"。

**问题 2：目标定义粒度**

SW Master Agent 的 Spec 是 1039 行的精确文档，定义了 Phase A 到 Phase H 的完整任务分解。但实际执行中 Agent 频繁遇到"Spec 不够精确"的问题（如 4 个 Spec ambiguities, 多个 Spec Amendment）。

**建议**：
- 对于自治系统，Spec 应分为两层：**高层决策 Spec**（人工撰写，定义"为什么做"和"做什么"）+ **细部实现 Spec**（Agent 在第一轮实现后自动生成并请求人工 review）。
- 不要追求"一次性写完完美 Spec"——接受 Spec 在实现过程中自然迭代。

### 3.4 思维逻辑

**问题：缺乏"阶段性停下来审视"的习惯**

文献调研项目在 7月20-21日密集产出后，7月22日做了简单的 PDF 归档和索引生成，然后人工工作完全停止。没有出现这样的审视时刻："我已经有了四大方法路线的深度调查和横向对比——现在我需要在哪条路线上继续深入？哪篇论文需要精读？这对 SW 项目的 Phase G 设计有什么具体影响？"

SW Master Agent 也存在同样问题——它忠实地按 Spec 推进 Phase G Tier 1 → Tier 2，但从未主动质疑"Born 修正对分子体系的实际改善有多大？是否值得投入 Tier 2 的 Schwinger 变分复杂工程？"

**建议**：
- 设定"每周审视节点"：固定时间（如每周五晚）进行 15 分钟的人工审视
  1. 回顾本周产出
  2. 评估下周方向是否需要调整
  3. 判断自治系统是否需要干预（暂停/加速/改方向）
- 审视模板：
  ```
  - 本周目标：[原定目标]
  - 实际完成：[差距分析]
  - 新发现/意外：[重要发现]
  - 下周调整：[方向/优先级/停止项]
  ```

### 3.5 自治系统治理

**SW Master Agent 需要人工介入的预警信号**：
1. ⚠️ **max_runs 即将耗尽**（当前 58/60）→ 需要立即决定：扩展 max_runs 或暂时 PAUSE
